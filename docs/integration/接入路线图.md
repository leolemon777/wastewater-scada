## 要解决的问题

污水站数据当前仍以本地演示为主。纯水房已具备“双源”入口：默认继续使用 `src/store/demoScenarios.ts`，本机 SCADA Hub 配置真实 PLC 后由 WebSocket 切换到已复核的只读 PLC 快照。Hub 默认禁用，因此不会在未配置时误关演示或连接现场设备。

目标：把现场真实数据（7 罐体 C# 上位机、多台 M100、后续 PLC/仪表）接入，替换演示数据，最终现场能实时监控和下发控制。

## 目标架构

```
7罐体设备 ──→ C# 罐体上位机(Tank Controller)──┐
   (本地自动闭环)                                │
多台 M100(网桥/网线)──────────────────────────┼─→ SCADA Hub ─→ Web 前端 ─→ useScadaStore
                                                 │   (唯一出口)                   ↑
纯水房 FX3GA + ENET-ADP ──MC 1E只读───────────┘                         真实数据替代对应 demo

M100 内置 4G ──→ 有人云/有人组态(独立链路，保持启用，不改动)
```

三条铁律：

1. **Web 前端不直连任何设备**（M100 / C# 上位机 / PLC），只连 SCADA Hub。
2. **已单独授权的控制命令必须经 Hub**：确认、限频、超时回读、失败兜底；纯水 PLC 第一阶段没有控制能力，不能套用本条开放控制。
3. **M100 内置 4G 走有人云**是独立链路，与本地总控互不影响，保持现状。

## 三个服务角色

| 角色 | 职责 | 现状 |
| --- | --- | --- |
| **SCADA Hub** | 唯一数据汇总中心；统一归一化；对前端 REST/WS；日志报警 | `.NET 8` 骨架和纯水三菱 PLC 只读 adapter 已完成；其他设备 adapter 待续建 |
| **Tank Controller** | 7 罐体自动加水/加酸/液位/pH 闭环；上报状态；受高级命令 | C#（已定方向） |
| **M100 Adapter** | 读 DI/DO/AI；执行 DO 控制；点位映射为标准 tag | Hub 内部模块，接口已验证 |

## M100 现场已验证信息

- 现行 IP 分配见 [`./M100-IP配置-现行版本.md`](./M100-IP配置-现行版本.md)（2026-08-19 实测更新）：气浮 `.31`、地下池 `.8`、收集池液位 `.30`、收集池流量计 `.32`、药剂房电机 `.33`（未验证）、混合池**故意保留默认 `.7`**（现场唯一）
- 读 IO `http://<ip>/ioread.cgi?read`；`.7/.8/.31` 均已开启 web 登录认证（Basic）；写 DO `iowrite.cgi` 未用、禁盲写
- DO 物理输出正常（实测 1 秒级闪烁）
- **不支持 TLS**，不要用 8883 TLS MQTT
- 有人云保持启用（485 点表数据只上报有人云，本地 `:26` 透传读不到——主站互斥）；自定义 MQTT 关闭后云端恢复在线
- **2026-08-19 数据面实测**：气浮 pH（AI1 4-20mA/0-14，`(mA-4)/16*14`）+ 曝气/刮沫 DO、地下池液位（AI1 4-20mA/0-5m）两路稳定可采；`.30/.32` 差传感器接线；混合池 485 数据卡通路（三选一：有人云查看 / 仪表加模拟量接 AI / 边缘网关）

## 统一协议要点

- **信封** `scada.v1`：所有消息带 `schema / messageType / sourceId / sourceType / seq / timestamp / quality / payload`
- **质量分级**：`good` / `stale`(通讯异常 >5s) / `offline`(>15s)
- **设备 ID**：罐体 `tank-01..07`、M100 `m100-01..`
- **Tag 命名**：`tank-01.level`、`tank-01.ph`、`m100-01.do01`、`m100-01.ai01`
- **报警**：统一由 Hub 生成（源离线、急停、液位高高/低低、pH 超限、加酸泵故障、DO 写入失败、命令超时等）

## Hub 对前端的接口

```
GET  /api/pure-water/plc/snapshot     # 当前纯水 PLC 全量快照
GET  /api/pure-water/plc/status       # 当前纯水 PLC 数据源状态
GET  /api/health                      # Hub 健康和只读标志
WS   /ws/scada                        # 实时推送
```

纯水第一阶段 WS 事件类型：`purewater.plc.snapshot` / `source.status`。控制事件和控制 API 不存在。其他设备的统一快照、增量和命令协议仍按 [`总控统一数据协议.md`](总控统一数据协议.md) 后续扩展。
