# M100 网桥现场通讯调试记录 - 2026-06-30

本文件记录 2026-06-30 现场网桥、M100、有人云与本地上位机联调过程。后续继续接入真实数据前，先读本文件，再看 `./M100本地上位机接入上下文.md` 和 `接入路线图.md`。

## 当前目标

现场希望保留原有有人云采集，同时让本地污水 SCADA 上位机也能拿到 M100 已采集的数据。

目标链路：

```text
现场仪表/执行器
  -> RS485 / DO
  -> 远端 M100
  -> 网桥 / 网线
  -> 本地现场电脑
  -> SCADA Hub / Web 前端

远端 M100 内置 4G
  -> 有人云继续采集和查看
```

关键限制：

- 现场距离远，电脑不在 PH 仪表旁边，不能用本地 USB-485 旁路监听。
- 不能让本地电脑和有人云边缘采集同时主动轮询同一条 RS485 总线，否则会形成两个 Modbus 主站抢总线。
- 本地系统应优先接收 M100 已采集并主动上报的数据，而不是再通过 `192.168.0.7:26` 抢读串口1。

## 本地抢读串口的测试结果

目标是验证是否能通过网桥访问 `192.168.0.7:26`，再透传到 RS485 串口1读取 PH。

测试过的请求：

```text
端口: 192.168.0.7:26
从站: 1
功能码: 04 / 03
地址: 0 / 1
```

典型 RTU 请求：

```text
01 04 00 00 00 01 31 CA
01 04 00 01 00 01 60 0A
01 03 00 00 00 01 84 0A
01 03 00 01 00 01 D5 CA
```

还扫描了从站地址 `1-10`，功能码 `04`，起始地址 `0`。

结果：

```text
全部 <no response>
```

状态计数变化：

```text
rxcounta 增加
txcounta 仍为 0 bytes
```

解释：

- M100 以太网侧收到了本地电脑发过去的请求。
- 但 M100 没有把任何数据返回给本地电脑。
- 这不等于 PH 点位配置错误。用户现场确认有人云已经能读到该数据，因此点表、485、仪表参数对有人云采集路径大概率是正确的。
- 更可能的原因是有人云边缘采集正在作为唯一主站使用 M100 串口1，本地 Socket 透明读不适合作为第二主站抢读同一条 485。

结论：后续不要继续把 `192.168.0.7:26` 当作稳定的数据读取方案。

## 有人云与本地同时拿数据的判断

用户目标：有人云继续采集，本地 SCADA 也拿同一份数据。

不可取方案：

```text
有人云边缘采集主动轮询 RS485
本地电脑也通过 192.168.0.7:26 主动轮询 RS485
```

原因：同一条 Modbus RTU/RS485 总线通常只能有一个主站主动轮询。两个主站会导致抢总线、冲突、丢包，且 M100 Socket 也未返回数据。

可行方向：

1. 让 M100 采集一次，然后同时上报给有人云和本地。
2. 如果 M100 固件支持有人云边缘采集同时启用本地 MQTT/HTTP 上报，则本地电脑接收 M100 主动上报。
3. 如果 M100 固件不支持双路上报，则需要额外边缘设备/网关作为唯一采集主站，再分别转发给有人云和本地 SCADA。

为了验证 M100 是否能在有人云在线时额外连接本地 MQTT，本次已做准备和测试：

### 模拟量读取方案

现场后续可优先确认 PH 仪表是否有独立模拟量输出。

常见端子/标识：

```text
AO+ / AO-
I+ / I-
4-20mA
0-10V
模拟输出
变送输出
```

如果有空闲 `4-20mA` 或 `0-10V` 输出，可用模拟量采集模块绕开 RS485 主站冲突：

```text
PH仪表模拟量输出
  -> AI模拟量采集模块
  -> 以太网/网桥/MQTT/Modbus TCP
  -> 本地SCADA
```

建议硬件关键词：

- `4-20mA模拟量采集模块`
- `AI模拟量输入模块`
- `4-20mA转以太网模块`
- `4-20mA转Modbus TCP模块`
- `带模拟量输入的边缘网关`

注意事项：

- 必须确认仪表模拟输出类型：有源/无源、二线/三线/四线。
- 必须确认量程，例如 `4mA=0pH`、`20mA=14pH`。
- 若量程是 `0-14pH`，典型换算为：`pH = (mA - 4) / 16 * 14`。
- 模拟量只能拿当前值，通常拿不到仪表诊断、报警、温度补偿等扩展信息。
- 远距离不要拉模拟量长线回本地电脑；采集模块应放在仪表附近，再通过网桥/网线回传。

### 远距离推荐架构

不要把 USB 或 RS485 长距离拉回中控电脑。远端采集、本地网络回传更稳：

```text
PH仪表
  -> RS485旁路监听 / AI模拟量采集 / 边缘网关
  -> 现场网桥从站
  -> 主网桥
  -> 本地SCADA
```

长期可选硬件：

- `RS485串口服务器`
- `Modbus RTU转TCP网关`
- `RS485转以太网网关`
- `工业边缘网关`
- `AI模拟量采集网关`

选型建议：

- 工业级、隔离型 RS485/AI。
- 支持 9-36V DC 供电。
- 支持 Modbus TCP、MQTT 或 HTTP 上报。
- 现场有雷击/长线风险时优先选带浪涌保护的型号。

注意：

- 这个接收器是临时 Python probe，不是常驻服务。
- 它只接收 MQTT CONNECT/PUBLISH/SUBSCRIBE/PING，不主动访问 M100，不写设备配置。
- 本地电脑当时实际 IP 是 `192.168.0.60`，不是 M100 MQTT 初始默认配置里的 `192.168.0.201`。
- 尝试给以太网添加 `192.168.0.201/24` 因权限不足失败，需要管理员 PowerShell。

后续要继续拿点表数据，有两条路：

## 2026-07-02 多台 M100 默认 IP 冲突与模拟量读取

现场确认：每个网桥后面都有一台 M100，且当前都保持默认数据 IP：

```text
192.168.0.7
```

这会导致多台 M100 在同一网桥二层网络里发生 IP 冲突。本地电脑访问 `192.168.0.7` 时，只能读到当前 ARP 抢答成功的那一台，不能区分它属于地下池、混合池、气浮池或其他模块。因此：

- 不能把 `192.168.0.7` 的读取结果当成“所有 M100”的结果。
- 当前模拟量读取结果只代表本地网络里当前响应 `192.168.0.7` 的那台 M100；2026-07-02 现场判断当前读到的是气浮池 M100，不代表地下池液位计模拟量。
- 若多台 M100 同时在线且 IP 相同，读数可能不稳定，MAC/设备归属也可能变化。

| 点位 | 寄存器 | 返回 | 解析 |

说明书确认：

- M100 AI 支持 `4-20mA` 电流输入。
- AI 使用 `AI` 端子和 `COM` 端子。
- AI 数据为 32 位单精度浮点数，单位 `uA`，换算 `mA = 返回值 / 1000`。

四线制液位计接线原则：

```text
液位计电源+        -> 24V+
液位计电源-        -> 24V-
液位计4-20mA输出+  -> M100 AI1 或 AI2
液位计4-20mA输出-  -> M100 COM
```

## 当前结论

1. 网桥管理网段 `192.168.2.x` 和 M100 数据网段 `192.168.0.x` 必须分清。
2. 气浮池 M100 是 `192.168.0.7`，不是 `192.168.2.70`。
3. 气浮池 DO 状态已可本地读取：曝气和刮沫当前均为 `1`。
4. 气浮前端 PH 是 RS485 串口1点表数据，不在 `ioread.cgi` 的 `ai[]` 中。
5. 有人云已能采集到 PH 时，不要再假设点表或 485 接线错误。
6. 本地通过 `192.168.0.7:26` 主动读 PH 没有回包，不应作为最终方案。
7. 已验证 M100 可以主动连接本地 MQTT：`192.168.0.7 -> 192.168.0.60:1883`。
8. 当前没有收到 PH 上报数据，因为普通 MQTT 发布项未启用，点表上报又依赖边缘计算上报配置。
9. 已验证本地边缘计算网关与有人云边缘计算互斥，不能用 `edgeen=1` 实现双路。
10. WebSocket/隐藏网页接口未发现有人云边缘采集缓存的只读出口。
11. 下一步不是继续测网络，而是换架构：优先做 RS485 旁路监听，或增加现场边缘网关/小主机作为唯一采集主站。
12. 若 PH 仪表有空闲模拟量输出，AI 模拟量采集是最省事且不抢 RS485 的方案。

## 下次继续的操作顺序

1. 确认现场有人云仍可看到气浮前端 PH 实时值。
2. 查看 PH 仪表端子/说明书，确认是否有空闲 `4-20mA` 或 `0-10V` 模拟量输出。
3. 若有模拟量输出，优先采购/测试 AI 模拟量采集模块，通过网桥回传。
4. 若没有模拟量输出，现场加 RS485 旁路监听设备，只监听 M100 与 PH 仪表的 Modbus RTU 报文。
5. 若旁路监听不方便，改方案为增加现场边缘网关/小主机作为唯一采集主站，再分别转发给有人云和本地 SCADA。
6. 不要再把 `192.168.0.7:26` 作为主要方案反复抢读。
