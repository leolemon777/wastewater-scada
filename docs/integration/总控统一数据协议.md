# 总控统一数据协议

## 设计目标

本协议用于把 7 个罐体 C# 上位机、多台 M100 模块、后续 PLC/仪表数据统一接入总控系统。

核心原则：

- 总控后端是唯一数据汇总中心
- Web 前端不直接连接 M100 或 C# 上位机
- C# 上位机负责 7 个罐体的本地自动控制闭环
- 总控系统负责统一监控、报警、记录和高级指令下发
- 无线网桥只做二层透传，等同于无线网线，不承担协议逻辑

## 总体架构

```text
7罐体现场设备
  -> C#罐体上位机
  -> 无线网桥
  -> 总控后端
  -> Web总控前端

多台M100
  -> 网线/无线网桥
  -> 总控后端
  -> Web总控前端

M100内置4G
  -> 有人云/有人组态
```

## 服务角色

### SCADA Hub

总控后端服务，负责：

- 接收 C# 罐体上位机数据
- 轮询或接收多个 M100 数据
- 统一归一化数据
- 对前端提供 REST / WebSocket
- 记录操作日志、报警日志、通讯状态
- 做控制命令确认、限频、超时和回读

建议默认地址：

```text
http://127.0.0.1:18080
ws://127.0.0.1:18080/ws/scada
```

现场部署时可改为现场电脑局域网 IP，例如：

```text
http://192.168.0.100:18080
ws://192.168.0.100:18080/ws/scada
```

### Tank Controller

C# 罐体上位机，负责：

- 7 个罐体自动加水
- 7 个罐体自动加酸
- 液位、pH、阀门、泵、模式、报警的本地闭环控制
- 向 SCADA Hub 上报状态
- 接收 SCADA Hub 的高级控制命令

### M100 Adapter

总控后端内部模块，负责：

- 读取 M100 在线状态
- 读取 M100 DI/DO/AI
- 接收或轮询 M100 采集点数据
- 执行经过确认的 DO 控制命令
- 将不同 M100 的点位统一映射为标准 tag

## 统一消息信封

所有实时数据和命令都使用统一信封。

```json
{
  "schema": "scada.v1",
  "messageType": "tank.snapshot",
  "sourceId": "tank-controller-01",
  "sourceType": "tank-controller",
  "seq": 1024,
  "timestamp": "2026-05-25T12:00:00.000Z",
  "quality": "good",
  "payload": {}
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `schema` | 固定为 `scada.v1` |
| `messageType` | 消息类型 |
| `sourceId` | 数据来源唯一 ID |
| `sourceType` | `tank-controller` / `m100` / `scada-hub` / `frontend` |
| `seq` | 来源内递增序号 |
| `timestamp` | ISO 时间 |
| `quality` | `good` / `stale` / `bad` / `offline` |
| `payload` | 具体数据 |

## C# 罐体上位机上报

### 上报接口

```text
POST /api/tank-controller/snapshot
```

### 上报周期

建议 1 秒 1 次。通讯异常超过 5 秒，总控判定该来源 `stale`；超过 15 秒判定 `offline`。

### 数据格式

```json
{
  "schema": "scada.v1",
  "messageType": "tank.snapshot",
  "sourceId": "tank-controller-01",
  "sourceType": "tank-controller",
  "seq": 1024,
  "timestamp": "2026-05-25T12:00:00.000Z",
  "quality": "good",
  "payload": {
    "controllerStatus": "running",
    "emergencyStop": false,
    "tanks": [
      {
        "id": "tank-01",
        "name": "1号罐",
        "mode": "auto",
        "level": 2.35,
        "levelUnit": "m",
        "targetLevel": 2.8,
        "ph": 6.82,
        "targetPh": 7.0,
        "waterValve": "open",
        "acidPump": "stopped",
        "autoWaterEnabled": true,
        "autoAcidEnabled": true,
        "alarmState": "none",
        "alarms": [],
        "interlocks": []
      }
    ]
  }
}
```

枚举值：

| 字段 | 可选值 |
| --- | --- |
| `controllerStatus` | `running` / `stopped` / `fault` / `maintenance` |
| `mode` | `auto` / `manual` / `maintenance` |
| `waterValve` | `open` / `closed` / `opening` / `closing` / `fault` |
| `acidPump` | `running` / `stopped` / `fault` |
| `alarmState` | `none` / `warning` / `critical` |

## C# 罐体命令

总控只能下发高级命令，不能绕过 C# 上位机直接执行加水、加酸底层动作。

### 命令下发接口

```text
POST /api/tank-controller/command
```

### 命令格式

```json
{
  "schema": "scada.v1",
  "messageType": "tank.command",
  "commandId": "cmd-20260525-000001",
  "sourceId": "scada-hub",
  "targetId": "tank-controller-01",
  "timestamp": "2026-05-25T12:00:05.000Z",
  "operator": "admin",
  "requireConfirm": true,
  "payload": {
    "tankId": "tank-01",
    "action": "setTargetPh",
    "value": 7.2,
    "ttlMs": 5000,
    "reason": "operator-request"
  }
}
```

### 命令动作

| action | value | 说明 |
| --- | --- | --- |
| `setMode` | `auto` / `manual` / `maintenance` | 设置罐体模式 |
| `enableAutoWater` | `true` / `false` | 启停自动加水 |
| `enableAutoAcid` | `true` / `false` | 启停自动加酸 |
| `setTargetLevel` | 数值 | 设置目标液位 |
| `setTargetPh` | 数值 | 设置目标 pH |
| `stopTank` | `null` | 停止单个罐体自动动作 |
| `emergencyStop` | `null` | 急停全部罐体动作 |
| `resetAlarm` | `null` | 复位报警 |

### 命令应答

```json
{
  "schema": "scada.v1",
  "messageType": "tank.commandAck",
  "commandId": "cmd-20260525-000001",
  "sourceId": "tank-controller-01",
  "timestamp": "2026-05-25T12:00:05.200Z",
  "accepted": true,
  "result": "queued",
  "message": "command accepted"
}
```

执行完成后继续上报 snapshot，由 snapshot 作为最终状态依据。

## M100 数据接入

### 后端读取接口

总控后端对前端提供：

```text
GET /api/m100
GET /api/m100/{deviceId}/status
GET /api/m100/{deviceId}/io
POST /api/m100/{deviceId}/do
```

### M100 IO 标准格式

```json
{
  "schema": "scada.v1",
  "messageType": "m100.ioSnapshot",
  "sourceId": "m100-01",
  "sourceType": "m100",
  "seq": 100,
  "timestamp": "2026-05-25T12:00:00.000Z",
  "quality": "good",
  "payload": {
    "ip": "192.168.0.7",
    "online": true,
    "do": {
      "do01": 0,
      "do02": 0
    },
    "di": {
      "di01": 0,
      "di02": 0
    },
    "ai": {
      "ai01": 0,
      "ai02": 0
    },
    "tags": {
      "node0101": 0,
      "node0102": 0,
      "node0201": 0
    }
  }
}
```

### M100 DO 控制

```text
POST /api/m100/{deviceId}/do
```

请求：

```json
{
  "commandId": "cmd-20260525-000002",
  "channel": "do01",
  "value": 1,
  "operator": "admin",
  "requireConfirm": true,
  "ttlMs": 3000,
  "reason": "manual-test"
}
```

应答：

```json
{
  "commandId": "cmd-20260525-000002",
  "accepted": true,
  "written": true,
  "readback": {
    "do01": 1,
    "do02": 0
  },
  "message": "ok"
}
```

安全规则：

- DO 控制必须由后端执行，前端不能直接请求 M100
- 默认禁止高频闪烁输出
- 每次写入后必须回读
- 控制失败或超时必须返回明确错误
- 测试闪烁类命令结束时必须强制 OFF

```text

```


## 数据映射规则

真实设备数据统一映射到当前前端 Zustand store。

示例：

| 来源 tag | 前端设备 | 字段 |
| --- | --- | --- |
| `tank-01.level` | `tk-collection-1` | `levelValue` / `levelPercent` |
| `tank-01.ph` | `tk-ph1` | `pH` |
| `tank-01.waterValve.state` | 后续 valve 设备 | `runStatus` |
| `m100-01.do01` | `p-lift-1` | `runStatus` |
| `m100-01.ai01` | 待定 | 待现场点表确认 |

映射表后续放在：

```text
src/store/tagMapping.ts
```

## 报警规则

报警统一由总控后端生成，再推送前端。

基础报警：

- 数据源离线
- C# 罐体上位机急停
- 液位高高/低低
- pH 超限
- 加酸泵故障
- 加水阀故障
- M100 离线
- M100 DO 写入失败
- 命令被拒绝或超时

报警级别：

```text
none
warning
critical
```

## 开发顺序

1. 先开发 SCADA Hub 本地后端骨架
2. 加 M100 最小接口：状态、IO 读取、DO 控制
3. 加 C# 罐体协议模拟器，用假数据模拟 7 个罐体
4. 前端接入 `/api/scada/snapshot` 和 `/ws/scada`
5. 开发真实 C# 罐体上位机
6. 接入真实 M100 多设备配置
7. 根据现场点表完善 `tagMapping`
