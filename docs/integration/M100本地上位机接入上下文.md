# M100 本地上位机接入上下文

## 目标

将当前污水 SCADA 前端从本地演示数据逐步接入现场 M100 网关数据。

目标链路：

```text
M100 网口/网桥 -> 现场电脑本地后端 -> Web 前端 SCADA
M100 内置 4G -> 有人云/有人组态
```

两条链路互不影响。本地上位机负责现场读取、展示和必要控制；有人云继续走 4G 做远程查看和原有组态。

## 当前前端状态

- 项目目录：`E:\Desktop\污水SCADA`
- 技术栈：React 19、TypeScript、Vite、Three.js / React Three Fiber、Zustand、lucide-react
- 当前无后端，使用 `src/store/demoScenarios.ts` 生成本地演示数据

  - `setEquipments(equipments)`

- 3D 场景和数据集控页面都从 Zustand store 读状态，适合后续替换真实数据源

## 前端接入原则

浏览器前端不要直接访问 M100。

原因：

- M100 本地接口是设备管理/IO 接口，直接暴露到浏览器不利于权限和安全控制
- 控制 DO/O 点需要确认、限频、日志和失败兜底
- M100 采集点数据更适合由本地后端接收、解析、归一化后再推给前端

推荐结构：

```text
M100 HTTP CGI / Socket 数据上报
  -> 本地后端服务 Python/Node/C#
  -> REST/WebSocket
  -> 前端 adapter
  -> useScadaStore
  -> 3D 视图 / 数据集控中枢 / 报警
```

2026-07-02 补充：

## 现场模块点位登记规则

每个现场模块的 M100 点位都可能不同，不能把某一台 M100 的点位表当成通用模板。后续按模块分别登记：

- 模块名称，例如气浮池、收集池、混合池、地下池、排水池 PH 等
- M100/网桥 IP 和现场安装位置
- DO/DI/AI/寄存器点位、读写属性、数据类型、存储方式
- 真实含义、SCADA 映射、单位/缩放系数、是否已实测
- 未确认点位单独标注，不直接接入正式 UI

## 2026-06-30 气浮池模块 M100 点位备注

本节只适用于气浮池模块，不代表其他模块。

现场截图确认的气浮池模块点位：

| 序号 | 变量名称 | 变量类型 | 数值类型 | 寄存器 | 读写 | 存储方式 | 建议 SCADA 映射 |
|---:|---|---|---|---|---|---|---|
| 1 | 曝气 | 直采变量 | bit | DO00001 | 读写 | 变化存储、定时存储 | `tk-daf.aerationRunning` |
| 2 | 刮沫 | 直采变量 | bit | DO00002 | 读写 | 变化存储、定时存储 | `tk-daf.scraperRunning` |
| 3 | 气浮前端PH | 直采变量 | ushort | 40001 | 只读 | 变化存储 | `tk-daf.pH` 或新增 `tk-daf.inletPH` |

气浮前端 PH 来源说明：

- 该数据来自 M100 的 RS485 串口1下挂仪表，不是 M100 本机 `ai[]` 数据。
- 当前 `port1.json` 读到的串口1参数：`9600`、`8N1`、SocketA 本地 TCP 端口 `26`、TCP Server。
- 当前边缘点表显示：`device01 / node0101 / Modbus RTU / 串口1 / 从站地址1 / 功能码04 / 寄存器40001`。
- `node0102 -> 40002` 也存在于 M100 点表，但现场含义暂未确认。

现场实测 `192.168.0.7` 当前返回：

```json
{"do":[1,1],"di":[0,0],"ai":[0,0],"ao":[]}
```

含义：

- `do[0] = 1`：DO00001 / 曝气当前为开
- `do[1] = 1`：DO00002 / 刮沫当前为开
- `di[0..1] = 0`：两个 DI 当前为 0
- `ai[0..1] = 0`：两个本机 AI 当前为 0

M100 边缘计算点表当前读到：

```text
device01,node0101,40001
device01,node0102,40002
```

2026-06-30 只读通讯测试：

- 通过 TCP 透明口 `192.168.0.7:26` 向串口1发送 Modbus RTU 读包 `01 04 00 00 00 01 31 CA`，未收到回包。
- 同时试读功能码 `03` 也未收到回包。
- 测试后状态计数显示以太网侧 `rxcounta = 16 bytes`、`txcounta = 0 bytes`，说明 M100 收到了上位机请求，但没有返回现场仪表数据。

注意：

- 当前 `econfig.json` 显示 `edgeen = 0`，边缘计算网关未开启；状态页串口收发计数为 `0 bytes`，说明还没有看到 M100 正在轮询现场仪表。
- 若要拿到 PH 实时值，需要确认 M100 已开启边缘采集，或确认透明传输口 `26` 已绑定串口1，并核对 RS485 A/B 线、从站地址、波特率、校验位、功能码和寄存器偏移。

## 建议新增模块

统一协议已定义在：

```text
docs/总控统一数据协议.md
```

前端侧建议新增真实数据适配层，例如：

```text
src/services/scadaRealtimeClient.ts
src/store/tagMapping.ts
```

职责：

- 连接本地后端 WebSocket 或轮询 REST
- 将后端 tag 数据映射为当前 store 的设备 ID
- 真实数据接入时关闭或暂停 `demoMode`
- 控制按钮不直接改本地状态，应先发控制命令，等后端/设备状态回读后再更新 UI

后端侧建议提供：

```text
GET  /api/scada/snapshot
GET  /api/m100/io
POST /api/m100/do
WS   /ws/scada
```

控制接口必须包含：

- 操作确认
- 限频
- 日志
- 失败回读
- 必要时强制 OFF 兜底
