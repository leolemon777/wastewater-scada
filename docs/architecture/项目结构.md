# 项目结构与模块边界

## 分层原则

项目按“应用组合、业务状态、场景呈现、界面呈现”分层。通讯适配层只能写入 store；设备组件和 UI 只读取 store，不直接处理 PLC/MQTT/HTTP 协议。

## 源码职责

| 目录 | 主要职责 | 依赖方向 |
|---|---|---|
| `src/app/` | 组合 Canvas、场景、UI 和错误边界 | 可依赖 components、store |
| `src/store/` | 设备目录、报警、KPI、演示数据和控制动作 | 不依赖 React 视图组件 |
| `src/components/scene/equipment/` | 单体设备模型和设备状态表现 | 可依赖 store、scene/shared |
| `src/components/scene/piping/` | 管道几何、连接件、端口坐标和颜色语义 | 不依赖具体工艺段 |
| `src/components/scene/sections/` | 工艺段布局与设备/管路组合 | 可组合 equipment、piping、site |
| `src/components/scene/site/` | 平台、厂房、物流和场地物件 | 不承载设备业务状态 |
| `src/components/scene/shared/` | 材质、标签、着色器和场景通用能力 | 不依赖具体工艺段 |
| `src/components/ui/` | 看板、报警、详情和场景控制 | 通过 store 获取业务状态 |
| `src/styles/` | 全局 token、主题和 UI shell 样式 | 由 `src/main.tsx` 统一引入 |

## 新文件放置规则

- 新增设备模型放入 `equipment/`，用稳定设备 ID 从 store 取数。
- 新增管件或通用管路算法放入 `piping/`，不要复制到单个 section。
- 仅属于某一工艺区域的坐标、布局和组合放入 `sections/`。
- 厂区非工艺设备放入 `site/`。
- 多个设备或工艺段复用的场景能力放入 `shared/`。
- 新的真实数据适配器应单独建立 `src/adapters/`，并只调用 store 写入方法。

## 验证

`scripts/check-scene.mjs` 会自动发现并按文件名顺序执行 `scripts/checks/scene/` 下的所有检查。修改 3D、管路、布局或设备 ID 后运行：

```bash
npm run verify:scene
npm run lint
```
